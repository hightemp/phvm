# phvm 1.1.0

This release adds project-local PHP selection and shell completion, and makes PHP, Composer, extension, and configuration changes safer to recover from failures. It includes all changes since v1.0.6; the previously prepared 1.0.7 version was never published.

## Highlights

- `phvm use` without an argument reads the nearest `.php-version` from the current directory or its parents. The file accepts installed versions and local aliases; an explicit argument takes precedence.
- Bash, Zsh, Fish, and PowerShell initialization now quotes the selected phvm root, avoids duplicate `PATH` entries, and provides completions from installed versions and aliases.
- PHP source installations are staged, validated, and published with rollback and interruption recovery. Concurrent changes to managed state are serialized.
- Composer updates verify the downloaded PHAR and the target PHP runtime before replacing the active copy. Composer storage survives cache cleanup.
- PECL extension operations identify modules by exact name, validate built artifacts before publication, record ownership, and remove only owned files. An optional `--sha256` pins a PECL archive; the default verifies available channel and package metadata.
- Download and filesystem handling now reject unsafe paths, unverified or corrupt artifacts, and invalid PHP signatures before execution or publication.
- `phvm doctor` checks the current PHP by default and probes build tools and libraries. Configuration and configure-flag precedence are shared across installation and diagnosis; CLI failures use consistent exit codes and stderr diagnostics.

## Behavior changes

- Saved ini profiles are exact snapshots of `php.ini` and `conf.d`. Applying one removes `conf.d` files absent from the snapshot. Built-in development and production profiles still change only `php.ini`.
- `phvm doctor` requires a valid current PHP unless `--php` selects a version. `phvm use` without an argument requires a valid `.php-version`; it does not silently select a default alias.
- Building phvm from source now requires the Go version declared in `go.mod` (Go 1.27.1 for this release).

## Validation

CI runs race tests, lint, vulnerability checks, a reviewed gosec baseline, and archive smoke tests on Linux, macOS, and Windows. Separate required scenarios exercise real Composer and PECL downloads and a native Redis extension build on Linux. The release workflow validates the tag and artifacts before publication.
