# phvm 1.2.0

This release lets each installed PHP version use its own compatible Composer, adds useful build-failure summaries, and checks memory and disk capacity before local source builds.

## Composer for each PHP version

- Composer PHARs are stored separately at `$PHVM_DIR/tools/composer/<php-version>/composer.phar`, outside the disposable cache. Updating Composer for PHP 8.3 no longer changes the copy used by PHP 5.6.
- `phvm composer install` selects the newest compatible stable release using Composer's official metadata. Older supported PHP versions can select Composer 2.2 LTS.
- `phvm composer install --php 5.6 --version 2.2.30` installs an exact release. The downloaded SHA256 and the version reported by the selected PHP are checked before publication.
- Failed downloads, incompatible candidates, version mismatches, and launcher-publication failures preserve the prior PHAR. HTTPS redirects to HTTP are rejected.
- Existing shared and cached Composer installations migrate to separate PHARs with runtime checks. `cache clear` preserves installed Composer.

## Short build diagnostics and complete logs

- A failed PHP build reports its stage, one relevant error, a practical hint, and the full install-log path instead of flooding the terminal with repeated linker errors.
- The install log includes private dependency builds and compiler/linker details from `config.log` when configure fails.
- Recognized URL credentials, labelled secrets, authorization headers, and known sensitive environment values are redacted. New and reused install logs have owner-only permissions.

## Memory and disk checks

- Automatic jobs account for available memory and CPU count. A positive `--jobs` keeps priority over the heuristic.
- Makefile commands preserve user-supplied `GOFLAGS`, including Go build parallelism limits used on machines with limited memory.
- PHP and PECL installs check estimated free space before source extraction and again before installation or publication. Forced PHP reinstalls also account for the existing installation's files.
- Capacity errors report the phase, path, and estimated required/available MiB. These estimates help avoid predictable failures; memory and disk availability may still change during a build.

## Behavior and upgrade notes

- `composer update --php X` updates only X's Composer; omitted `--php` selects current PHP.
- `composer install --global` remains available as a shared download seed for later per-PHP enablement. Enabled PHP versions use their own PHARs.
- Automatic jobs use one job when available memory cannot be measured, including the current Windows fallback. PHP source-building and old-PHP runtime coverage have the limits documented in the scenario matrix.
- Upgrading the phvm binary preserves existing PHP installations and configuration. Composer migration happens when the relevant commands run.

The changes were developed through TDD and checked with race tests, lint, vet, vulnerability checks, and a gosec baseline that blocks new findings. The required suite now includes 30 deterministic scenario groups, six real-PHP runtime groups, and two upstream Composer/PECL groups on Linux.
